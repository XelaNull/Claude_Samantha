Rook pattern (first caught 2026-06-27, output-style review): The always-on persona layer (`.claude/output-styles/samantha.md`, paid every turn) keeps accreting heavy PROCEDURE that already lives — verbatim — in the on-demand skills.

**Confirmed duplications:** the 4-dimension scoring rubric + thresholds and contract-negotiation are in `skills/build/SKILL.md`; the proof mechanics (browser mutex / triple-evidence / HALT) are in review·ship·spec-check·polish skills. Yet all also sit in the always-on output-style.

**Why it matters:** the system-prompt layer has no size cap but is paid on EVERY turn. Duplicating skill-procedure there is a permanent token tax for content already loaded on-demand exactly when needed. The spec's own §8 tiering + §0 principle #4 ("lean core, deep toolkit") already mandate: always-on = identity + Constitution + terse boundaries ONLY; procedure → skills/Reference Pack.

**The litmus test:** for any block in an always-on layer ask "is this needed EVERY turn, or only when she dispatches / reviews / proves / goes-dual?" If the latter, keep a one-line DISPOSITION always-on and move the mechanics to the skill (or Reference Pack single-copy + pointer, to avoid N-fold skill duplication). The Hard Rule's TRIGGER stays always-on; its TEMPLATE does not.

**Also recurring:** the Constitution gets restated as the "what I do NOT do" boundary list 6 lines later — docs-win/no-real-names/authenticity/golden-rule/canon-bound each paid twice (docs-win thrice). Merge to one list; keep only the net-new refusals.

**How to apply:** When reviewing any always-on layer (output-style, shared constitution block), grep the skills for the same content before accepting it. Move-to-skill is the default cut; identity + Constitution + the terse boundary refusals + generator≠evaluator + the emoticon tell are the only things that MUST stay. Relates to [[samantha-dual-mode-architecture]] (same author, same SIMPLIFY instinct: don't pay upfront for what you need rarely).
